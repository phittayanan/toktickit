# Lab 4 API Contract

Extends `docs/lab-03/api-spec.md`, which stays in force. Rule and criterion
numbers (BR, AC) refer to `specification.md` in this folder. "L3 API §n"
means a section of the Lab 3 contract. "Staff" means IT Staff or
Administrator; a "Finished" Ticket is Closed or Cancelled.

## 1. Conventions

### 1.1 Transport

As L3 API §1.1 to §1.3: JSON bodies, ISO 8601 UTC timestamps in responses,
the `tk_session` cookie, one allowed origin, and the `Origin` check on
state-changing requests. A timestamp in a request must carry a UTC offset
(`2026-10-30T09:00:00+07:00` or `…Z`).

New enumeration on the wire:

- ActionTakenStatus: `PLANNED`, `DONE`, `CANCELLED`.

### 1.2 Errors

The body is as L3 API §1.4. Every error defined here carries `code`.

| Status | `code` | Meaning |
|---|---|---|
| 403 | `ACTION_TAKEN_EDIT_FORBIDDEN` | Staff user who is not the creator, the assignee, or an Administrator (BR-16) |
| 409 | `ACTION_TAKEN_CHANGED` | `expectedVersion` is stale (BR-13) |
| 409 | `ACTION_TAKEN_FINAL` | The Action Taken is Done or Cancelled (BR-10) |
| 409 | `DONE_ACTION_REQUIRED` | Resolving a Ticket with no Done Action Taken (BR-20) |
| 409 | `PLANNED_ACTION_REMAINS` | Resolving a Ticket with a Planned Action Taken (BR-20) |

Lab 3 codes keep their meaning; `TICKET_FINISHED` also covers Action Taken
writes.

### 1.3 Order of checks

L3 API §1.5 steps 1 to 3 (session, password change, role) run first. Role
is fixed by prefix, with one addition: `/api/requester` needs Requester.
`GET /api/tickets/:id/actions-taken` follows the shared-resource rule of
L3 API §6.

`POST /api/staff/tickets/:id/actions-taken` continues:

4. No such Ticket → `404`.
5. Body validation, including `assigneeId` → `400`.
6. The Ticket is Finished → `409` `TICKET_FINISHED`.
7. The `clientRequestId` already exists on this Ticket → `200` with the
   existing Action Taken (BR-15).

`PUT /api/staff/tickets/:id/actions-taken/:actionTakenId` continues:

4. No such Ticket, no such Action Taken, or it belongs to another Ticket →
   `404`.
5. Body validation, including a changed `assigneeId` → `400`.
6. The Ticket is Finished → `409` `TICKET_FINISHED`.
7. The session user may not edit it → `403`
   `ACTION_TAKEN_EDIT_FORBIDDEN`.
8. A stale `expectedVersion` → `409` `ACTION_TAKEN_CHANGED`.
9. The Action Taken is Done or Cancelled → `409` `ACTION_TAKEN_FINAL`.

Steps 6 to 9 of `PUT` and 6 to 7 of `POST` run inside the Ticket Change, so
they see the rows as they stand under the Ticket row lock. Assignee rows are
locked ahead of the Ticket, the module's fixed order.

### 1.4 Caching

Besides L3 API §1.6, `/api/requester/*` and `/api/staff/dashboard` responses
carry `Cache-Control: no-store`, so a dashboard is never served stale.

### 1.5 Shared shapes

`ActionTaken`:

```json
{
  "id": 88,
  "ticketId": 42,
  "actionAt": "2026-10-30T02:00:00.000Z",
  "description": "Replaced the laptop battery.",
  "result": "Charge now holds for 7 hours.",
  "status": "DONE",
  "assignee": { "id": 12, "name": "Wichai Phromma" },
  "followUpRequired": true,
  "followUpNote": "Check the charge again next week.",
  "attachmentNotes": "See battery-report.pdf.",
  "createdBy": { "id": 15, "name": "Siriporn Kaewmanee" },
  "createdAt": "2026-10-30T02:10:00.000Z",
  "updatedAt": "2026-10-30T02:10:00.000Z",
  "version": 1,
  "canEdit": false
}
```

`result`, `followUpNote`, and `attachmentNotes` are null when empty. Text is
plain text; clients render it as text (BR-38). `canEdit` is calculated for
the session user: true only when the Action Taken is Planned, the Ticket is
Unfinished, and the user is its creator, its assignee, or an Administrator.
It is always false for a Requester. It is feedback for the client; the
backend still enforces the rule.

## 2. Actions Taken

### 2.1 GET /api/tickets/:id/actions-taken

Usable by the Ticket's Requester and by staff.

- **Success `200`**: an array of `ActionTaken`, every status included,
  ordered by `createdAt` descending, ties by `id` descending. Empty when
  there are none. Not paginated.
- **`404`**: `{ "error": "Ticket not found", "code": "NOT_FOUND" }` for a
  missing Ticket, or for a Requester, one that is not theirs.

### 2.2 POST /api/staff/tickets/:id/actions-taken

Creates an Action Taken (BR-01 to BR-12).

- **Request**:
  ```json
  {
    "clientRequestId": "6f1c2b1e-7a44-4f7e-9a36-1d0c3d3f7a10",
    "actionAt": "2026-10-30T09:00:00+07:00",
    "description": "Replaced the laptop battery.",
    "result": "Charge now holds for 7 hours.",
    "status": "DONE",
    "assigneeId": 12,
    "followUpRequired": false,
    "followUpNote": null,
    "attachmentNotes": null
  }
  ```

| Key | Required | Rule |
|---|---|---|
| `clientRequestId` | Yes | UUID, generated by the client once per create form and reused on retry |
| `status` | Yes | `PLANNED` or `DONE`. `CANCELLED` is `400` |
| `description` | Yes | Trimmed, 1 to 2000 characters |
| `actionAt` | No | Default: now. Not after now when `status` is `DONE` |
| `assigneeId` | No | Default: the session user. Must be an active IT Staff or Administrator |
| `result` | When `DONE` | Trimmed, at most 2000 characters; string or null |
| `followUpRequired` | No | Boolean, default `false` |
| `followUpNote` | When `followUpRequired` | Trimmed, 1 to 2000 characters. Must be null or absent otherwise |
| `attachmentNotes` | No | Trimmed, at most 500 characters; string or null |

An empty optional string after trimming is stored as null. The creator, the
creation time, the version, and the Ticket come only from the session, the
server, and the path; any such key in the body is ignored.

- **Success `201`**: the created `ActionTaken`, version 1.
  `Ticket.updatedAt` is set to now.
- **Success `200`**: the `clientRequestId` was already used on this Ticket.
  The existing `ActionTaken` is returned and nothing changes, whatever the
  rest of the body says.
- **`400`** `VALIDATION_ERROR` with `field`: a rule above. For an unknown,
  inactive, or Requester id alike, `field: "assigneeId"` and `"Performed by
  must be an active IT Staff or Administrator user."`. For a future Done
  time, `field: "actionAt"` and `"A Done action cannot be dated in the
  future."`.
- **`404`**: no such Ticket.
- **`409` `TICKET_FINISHED`**.

### 2.3 PUT /api/staff/tickets/:id/actions-taken/:actionTakenId

Replaces the editable fields of a Planned Action Taken. Mark Done and Cancel
action are this request with `status` set (BR-08).

- **Request**:
  ```json
  {
    "expectedVersion": 1,
    "actionAt": "2026-10-30T09:00:00+07:00",
    "description": "Replaced the laptop battery.",
    "result": "Charge now holds for 7 hours.",
    "status": "DONE",
    "assigneeId": 12,
    "followUpRequired": false,
    "followUpNote": null,
    "attachmentNotes": null
  }
  ```
  Every key is required. `expectedVersion` is the version the client loaded,
  an integer of 1 or more. `status` is any ActionTakenStatus. The rules of
  §2.2 apply otherwise, with two differences: `assigneeId` is validated only
  when it differs from the stored value (BR-04), and a future `actionAt` is
  refused only for `DONE`.

- **Success `200`**: the updated `ActionTaken`. If any field changed,
  `version` rises by one and `updatedAt` and `Ticket.updatedAt` are set to
  now. If nothing changed, nothing moves (BR-14). `createdBy` and `createdAt`
  never change.
- **`400`**: as §2.2, or `expectedVersion` missing or invalid.
- **`403` `ACTION_TAKEN_EDIT_FORBIDDEN`**: `"Only the creator, the person
  performing it, or an Administrator can edit this action."`
- **`404`**: no such Ticket or Action Taken, or a mismatch of the two.
- **`409` `TICKET_FINISHED`**.
- **`409` `ACTION_TAKEN_CHANGED`**: `"This action was changed by someone
  else. Reload to see the latest version."` Nothing changes.
- **`409` `ACTION_TAKEN_FINAL`**: `"A Done or Cancelled action can no longer
  be changed."`

There is no `DELETE` route. Any other method on these paths answers `404`.

### 2.4 Assignee options

`GET /api/staff/eligible-owners` (L3 API §5.3) also supplies the Performed by
options: the rule is the same.

## 3. Staff Tickets

### 3.1 POST /api/staff/tickets/:id/status

The request and success body are as L3 API §5.6. When `status` is `RESOLVED`,
two checks follow `OWNER_REQUIRED`, in the same Ticket Change as the write:

- **`409` `DONE_ACTION_REQUIRED`**: the Ticket has no Done Action Taken.
  `"A ticket needs at least one Done action before it can be resolved."`
- **`409` `PLANNED_ACTION_REMAINS`**: it has a Planned Action Taken. `"Finish
  or cancel every Planned action before resolving this ticket."`

On any error nothing changes. The full order after validation is
`TICKET_FINISHED`, `STATUS_CHANGED`, `INVALID_TRANSITION`, `OWNER_REQUIRED`,
`DONE_ACTION_REQUIRED`, `PLANNED_ACTION_REMAINS`. No other transition is
gated (BR-23).

### 3.2 StaffTicket

`StaffTicket` (L3 API §5.2) gains one field:

```json
{ "actionTakenCounts": { "planned": 1, "done": 2, "cancelled": 0 } }
```

`allowedTransitions` keeps its meaning: the matrix targets from the current
status, regardless of the gate. The client uses `actionTakenCounts` to show
the gate's state (`ui-spec.md` §9); the backend enforces it either way.

## 4. Requester Tickets

`GET /api/tickets` (L2 and L3 API §4.1) changes in one way: `currentStatus`
accepts one or more Status values, comma-separated, and returns Tickets in
any listed status. A single value behaves as before. An invalid value is the
unchanged Lab 2 `400`.

`GET /api/tickets/:id` is unchanged; Actions Taken are read through §2.1.

## 5. Dashboards

All three are `GET` with no parameters and return only the fields shown.
Metrics are calculated per request (BR-28). With no matching data a count is
`0` and a list is `[]`; the response is still `200` (AC-36).

Common fields:

- `generatedAt`: the server time of the calculation.
- `recentSince`: the start of the recent window (BR-29), 00:00
  Asia/Bangkok six calendar days before today's Bangkok date, as a UTC
  timestamp.

### 5.1 GET /api/requester/dashboard

Role Requester; staff get `403`. Own Tickets only, from the session.

- **Success `200`**:
  ```json
  {
    "generatedAt": "2026-10-30T08:00:00.000Z",
    "recentSince": "2026-10-23T17:00:00.000Z",
    "openCount": 3,
    "waitingForRequesterCount": 1,
    "recentlyUpdated": [
      {
        "id": 42,
        "ticketNumber": "TKT-2026-000123",
        "summary": "Laptop battery drains quickly",
        "currentStatus": "IN_PROGRESS",
        "updatedAt": "2026-10-30T02:10:00.000Z"
      }
    ],
    "recentlyResolved": [
      {
        "id": 40,
        "ticketNumber": "TKT-2026-000120",
        "summary": "Printer offline on floor 3",
        "currentStatus": "RESOLVED",
        "resolvedAt": "2026-10-29T06:00:00.000Z"
      }
    ]
  }
  ```

| Field | Query (own Tickets) | Order and limit | Drill-down |
|---|---|---|---|
| `openCount` | `currentStatus` in `NEW`, `OPEN`, `IN_PROGRESS`, `WAITING_FOR_REQUESTER`, `REOPENED` | | `GET /api/tickets?currentStatus=NEW,OPEN,IN_PROGRESS,WAITING_FOR_REQUESTER,REOPENED` |
| `waitingForRequesterCount` | `currentStatus` is `WAITING_FOR_REQUESTER` | | `GET /api/tickets?currentStatus=WAITING_FOR_REQUESTER` |
| `recentlyUpdated` | `updatedAt` ≥ `recentSince` | `updatedAt` desc, `id` desc; 5 | Requester Ticket Detail |
| `recentlyResolved` | `currentStatus` in `RESOLVED`, `CLOSED`, and `resolvedAt` ≥ `recentSince` | `resolvedAt` desc, `id` desc; 5 | Requester Ticket Detail |

### 5.2 GET /api/staff/dashboard

Staff; a Requester gets `403`. `U` below is the six Unfinished statuses:
`NEW`, `OPEN`, `IN_PROGRESS`, `WAITING_FOR_REQUESTER`, `RESOLVED`, `REOPENED`.

- **Success `200`**:
  ```json
  {
    "generatedAt": "2026-10-30T08:00:00.000Z",
    "recentSince": "2026-10-23T17:00:00.000Z",
    "unassignedCount": 4,
    "ownedByMeCount": 6,
    "myPlannedActionsTakenCount": 2,
    "byStatus": {
      "NEW": 2, "OPEN": 3, "IN_PROGRESS": 5,
      "WAITING_FOR_REQUESTER": 1, "RESOLVED": 2, "REOPENED": 0
    },
    "byItPriority": { "LOW": 4, "MEDIUM": 6, "HIGH": 3 },
    "myPlannedActionsTaken": [
      {
        "id": 91,
        "ticketId": 42,
        "ticketNumber": "TKT-2026-000123",
        "description": "Replace the docking station.",
        "actionAt": "2026-10-31T02:00:00.000Z"
      }
    ],
    "urgent": [
      {
        "id": 42,
        "ticketNumber": "TKT-2026-000123",
        "summary": "Laptop battery drains quickly",
        "currentStatus": "IN_PROGRESS",
        "itPriority": "HIGH",
        "owner": { "id": 12, "name": "Wichai Phromma" },
        "updatedAt": "2026-10-30T02:10:00.000Z"
      }
    ],
    "recentlyUpdated": []
  }
  ```
  `recentlyUpdated` has the element shape of `urgent`. `owner` is null when
  unassigned. `byStatus` and `byItPriority` always hold every key shown.

| Field | Query | Order and limit | Drill-down |
|---|---|---|---|
| `unassignedCount` | Status in `U`, `ownerId` null | | `GET /api/staff/tickets?owner=unassigned&status=<U>` |
| `ownedByMeCount` | Status in `U`, `ownerId` is the session user | | `GET /api/staff/tickets?owner=me&status=<U>` |
| `myPlannedActionsTakenCount` | `ActionTaken` with `status` `PLANNED`, `assigneeId` the session user, Ticket status in `U` | | The items of `myPlannedActionsTaken` |
| `myPlannedActionsTaken` | As above | `actionAt` asc, `id` asc; 5 | Staff Ticket Detail of `ticketId` |
| `byStatus` | Count per status in `U` | | `GET /api/staff/tickets?status=<that status>` |
| `byItPriority` | Count per `itPriority` with status in `U` | | `GET /api/staff/tickets?itPriority=<value>&status=<U>` |
| `urgent` | Status in `U`, `itPriority` in `HIGH`, `MEDIUM` | `HIGH` first, then `updatedAt` desc, `id` desc; 5 | Staff Ticket Detail |
| `recentlyUpdated` | Any Ticket with `updatedAt` ≥ `recentSince` | `updatedAt` desc, `id` desc; 5 | Staff Ticket Detail |

The drill-downs use the queue parameters of L3 API §5.1 unchanged.

### 5.3 GET /api/admin/dashboard

Role Administrator; anyone else gets `403`. An Administrator calls this and
§5.2 for the IT Staff dashboard plus account counts.

- **Success `200`**:
  ```json
  {
    "generatedAt": "2026-10-30T08:00:00.000Z",
    "activeUsers": { "REQUESTER": 4, "IT_STAFF": 3, "ADMINISTRATOR": 1 }
  }
  ```

| Field | Query | Drill-down |
|---|---|---|
| `activeUsers.<role>` | Users with that role and `isActive` true | `GET /api/admin/users?role=<role>`, which also lists inactive users (BR-32) |

## 6. Continued APIs

Every other Lab 2 and Lab 3 endpoint, and `GET /api/health`, is unchanged.
Internal Notes never appear in any Lab 4 response to a Requester (ADR-0010).

## 7. Expected HTTP statuses (summary)

| Status | Meaning in this contract |
|---|---|
| 200 | Successful read or edit, or a repeated Action Taken create |
| 201 | Action Taken created |
| 400 | Invalid input |
| 401 | Not signed in, or session expired or ended |
| 403 | Password change required, role not permitted, disallowed origin, or no edit right on this Action Taken |
| 404 | Resource missing, not owned by the requesting Requester, or no such route |
| 409 | Request conflicts with the current state of the Ticket or Action Taken |
| 500 | Unexpected server error, generic body only |
